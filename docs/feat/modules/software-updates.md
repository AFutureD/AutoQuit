# 软件更新

用户可以从菜单栏检查 AutoQuit 新版本；有可信更新时继续安装，没有新版或检查失败时保留当前版本。

## 模块概览

- **实际入口**：菜单栏窗口形图标 > “Check for Updates…”。
- **可触达条件**：AutoQuit 正在运行，更新组件已完成启动。
- **前置条件**：首个正式版本已成功发布，检查时网络可访问 GitHub Releases；安装需要发布版本带有有效的 Developer ID、公证和 Sparkle 更新签名，并且 AutoQuit 位于可更新的位置。部分 Mac 会要求管理员授权。
- **主要结果**：用户确认当前已是最新，或安装新版本并重新打开 AutoQuit。
- **相关旅程**：[将 AutoQuit 更新到新版本](../journeys/update-autoquit.md)

## 用户目标

### 获取可信的新版本

用户想确认 AutoQuit 是否有新版，并在不手动寻找下载文件的情况下完成更新。

完成信号：更新后 AutoQuit 重新打开并恢复菜单栏入口；再次检查时不再把同一构建列为新版。没有新版时，更新窗口说明当前已是最新。

## 流程步骤

### 主流程：手动检查并安装更新

1. 点击菜单栏图标并选择“Check for Updates…”。
   - 系统反馈：显示更新检查进度。
   - 数据结果：读取发布源，不修改当前安装。
   - 规则引用：[`UPD-R-001`](#upd-r-001)
2. 有新版时，在更新窗口继续下载和安装。
   - 系统反馈：显示新版本信息和更新进度；部分 Mac 会要求输入管理员用户名和密码。
   - 数据结果：下载更新包并验证发布签名；验证完成前不替换当前版本。
   - 规则引用：[`UPD-R-002`](#upd-r-002)、[`UPD-R-003`](#upd-r-003)
3. 按更新窗口提示重新打开 AutoQuit。
   - 系统反馈：当前实例结束，新版本启动并恢复菜单栏入口。
   - 数据结果：应用版本更新；辅助功能授权、开机启动选择和应用规则不因更新而删除。
   - 规则引用：[`UPD-R-003`](#upd-r-003)

完成信号：AutoQuit 重新打开并恢复菜单栏入口；再次检查时不再把同一构建列为新版，原有规则仍可继续执行。

### 分支流程：没有新版本

1. 选择“Check for Updates…”。
   - 系统反馈：更新窗口说明当前已是最新。
   - 数据结果：当前安装不变。
   - 规则引用：[`UPD-R-002`](#upd-r-002)

结束状态：AutoQuit 继续运行当前版本。

### 分支流程：检查、验证或安装失败

1. 如果出现错误提示，关闭提示；如果下载后没有完成安装，确认 AutoQuit 位于“应用程序”文件夹，而不是只读磁盘映像或临时打开位置。
   - 系统反馈：返回当前运行状态；某些安装位置不可更新时，默认更新界面可能不显示错误提示。
   - 数据结果：当前安装不变，已有权限和规则不变。
   - 规则引用：[`UPD-R-004`](#upd-r-004)
2. 网络、发布源或安装位置恢复后，再次选择“Check for Updates…”；系统请求管理员授权时，由用户确认后继续。
   - 系统反馈：重新开始检查或安装。
   - 数据结果：重新读取更新信息。
   - 规则引用：[`UPD-R-001`](#upd-r-001)

结束状态：检查成功后回到主流程；持续失败时没有其他应用内更新入口。

## 完整能力

### 手动检查

菜单栏始终保留“Check for Updates…”入口。更新组件忙碌时，该入口会暂时不可用，避免同时开始多次检查。

### 定期检查

更新组件按标准提示询问用户是否允许自动检查。用户未允许时仍可使用菜单栏手动检查；允许后，组件会按保存的选择定期读取更新源。

### 验证与安装

新版本必须同时满足发布签名和 Sparkle 更新签名验证，才能替换当前安装。标准用户、受管理的 Mac 或不可写安装位置可能需要管理员授权；只读磁盘映像或临时打开位置可能无法更新。失败时继续保留当前可运行版本。

## 规则

### UPD-R-001

**规则：菜单栏启动一次明确的更新检查。**

- **条件**：AutoQuit 正在运行，更新组件当前可以开始检查。
- **行为**：用户选择“Check for Updates…”后，AutoQuit 读取配置的更新源并显示进度。
- **结果**：用户看到可安装的新版本、当前已是最新或检查失败结果。
- **限制或例外**：检查进行中时入口会暂时不可用。

### UPD-R-002

**规则：更新以发布构建版本判断新旧。**

- **条件**：更新源可访问且包含发布信息。
- **行为**：AutoQuit 比较当前构建版本与发布构建版本。
- **结果**：发布版本更高时进入更新流程，否则报告当前已是最新。
- **限制或例外**：版本信息缺失或无效时不能进入安装。

### UPD-R-003

**规则：只有通过签名验证的更新才能安装。**

- **条件**：用户选择安装新版本。
- **行为**：更新组件下载并验证发布包，验证成功后才替换应用。
- **结果**：成功时重新打开新版本；失败时保留当前版本。
- **限制或例外**：AutoQuit 不提供跳过验证的选项；系统可能要求管理员授权，应用位于只读或临时位置时可能无法替换。

### UPD-R-004

**规则：检查失败不改变当前安装。**

- **条件**：网络不可用、更新源不可访问、发布信息和签名无法通过检查，或当前安装位置无法更新。
- **行为**：更新组件停止本次检查或安装；通常会显示失败结果，但只读或临时安装位置等场景可能没有错误提示。
- **结果**：AutoQuit 继续运行当前版本，已有权限和规则保持不变。
- **限制或例外**：当前没有备用更新源或应用内诊断入口。

### UPD-R-005

**规则：定期检查取决于用户保存的选择。**

- **条件**：更新组件显示自动检查许可提示。
- **行为**：用户的选择决定后续是否自动读取更新源。
- **结果**：允许后定期检查；不允许时只在用户手动操作后检查。
- **限制或例外**：该选择由更新组件保存，当前设置窗口没有单独开关。

更新检查失败或新版无法安装时，按症状查看[用户摩擦点与恢复路径](../friction-points.md#update-check-failed)。

## 业务数据

### 软件更新信息

- **创建或更新**：每次发布 GitHub Release 时生成，包含版本、下载地址和更新签名。
- **持久化结果**：发布信息保存在外部更新源；当前 Mac 只保存更新组件所需的用户选择和安装状态。
- **主要用途**：判断是否有新版，并验证要安装的更新包。
- **删除影响**：更新源缺失时不能发现或安装新版本，当前安装不受影响。
- **完整生命周期**：[软件更新信息数据流](../data-flows.md#software-update-information)
